Dark ListBox: Items & Selection

Owner-draw is already familiar. Now we apply that same native model to a control that owns a collection of items and a current selection, then learn how the parent queries that state after LBN_SELCHANGE.

1. Same owner-draw model, new control contract

We are not going back to a bright stock control. Tutorial 04 already taught the owner-draw relationship: the child control keeps its native behavior while the parent handles the drawing request.

Carry the model forward

You already know why WM_DRAWITEM goes to the parent; now we're applying that same model to a different native control.

The new subject is the ListBox itself: it owns a collection of items, it owns the current selection, and it tells the parent when that selection changes.

native LISTBOX │ ├─ owns item collection ├─ owns current selection ├─ handles mouse / keyboard / scrolling └─ asks parent to paint rows │ ▼ LBN_SELCHANGE │ ▼ parent queries selection

2. Create a dark native LISTBOX

The child still comes from Windows' built-in LISTBOX class. The styles combine familiar owner-draw with the ListBox features this lesson needs.

mainCreateWindowExW — LISTBOX
invoke CreateWindowExW, 0, ListBoxClassName, 0,\
       WS_CHILD + WS_VISIBLE + WS_TABSTOP + WS_VSCROLL +\
       LISTBOX_LBS_NOTIFY + LISTBOX_LBS_OWNERDRAWFIXED +\
       LISTBOX_LBS_HASSTRINGS + LISTBOX_LBS_NOINTEGRALHEIGHT,\
       0, 0, 0, 0,\
       [MainWindow], IDC_LISTBOX, [wc.hInstance], 0

LBS_OWNERDRAWFIXED gives every row one fixed height. LBS_HASSTRINGS tells the owner-drawn ListBox that its items are real strings. LBS_NOTIFY asks it to notify the parent when selection changes, and LBS_NOINTEGRALHEIGHT lets our DPI-aware layout choose the exact control height.

3. LB_ADDSTRING adds items to control-owned storage

A ListBox is not just a painted rectangle. It maintains an internal item collection. The parent adds the five demo strings by sending ListBox messages.

AddDemoItemsfive fixed Unicode strings
invoke SendMessageW, [hListBox], LB_ADDSTRING, 0, sItemButton
invoke SendMessageW, [hListBox], LB_ADDSTRING, 0, sItemListBox
invoke SendMessageW, [hListBox], LB_ADDSTRING, 0, sItemListView
invoke SendMessageW, [hListBox], LB_ADDSTRING, 0, sItemTreeView
invoke SendMessageW, [hListBox], LB_ADDSTRING, 0, sItemTabControl

Because LBS_HASSTRINGS is active, USER32 copies each UTF-16 string into the ListBox's own item storage. The original labels in our data section are only the source of the insertion; they are not the ListBox's storage.

our UTF-16 string │ ▼ LB_ADDSTRING │ ▼ native ListBox copies it │ ▼ control-owned item collection

4. WM_MEASUREITEM is a creation-time contract

With LBS_OWNERDRAWFIXED, Windows asks the parent for one common row height through WM_MEASUREITEM.

WM_MEASUREITEMfixed row height
.wmmeasureitem:
        mov     rbx, [lparam]

        cmp     dword [rbx + MEASUREITEMSTRUCT64_LOCAL.CtlType], LISTBOX_ODT_LISTBOX
        jne     .default

        cmp     dword [rbx + MEASUREITEMSTRUCT64_LOCAL.CtlID], IDC_LISTBOX
        jne     .default

        mov     eax, [ScaledListItemHeight]
        mov     [rbx + MEASUREITEMSTRUCT64_LOCAL.itemHeight], eax

There is an important timing detail in the source: WM_MEASUREITEM may arrive during CreateWindowExW, before hListBox has been stored. That is why this handler identifies the request by control type and control ID instead of depending on the child HWND.

5. WM_DRAWITEM is familiar — but itemID is new

The row-painting mechanism deliberately reuses the Button lesson. Windows supplies an HDC, rectangle and native state. ODS_SELECTED decides which row appearance to use.

WM_DRAWITEMnative selection drives appearance
mov     eax, [rbx + DRAWITEMSTRUCT64_LOCAL.itemState]
test    eax, LISTBOX_ODS_SELECTED
jnz     .draw_selected

mov     rdi, [hListBrushNormal]
invoke SetTextColor, [rbx + DRAWITEMSTRUCT64_LOCAL.hDC], LISTBOX_TEXT_NORMAL
jmp     .have_row_style

.draw_selected:
mov     rdi, [hListBrushSelected]
invoke SetTextColor, [rbx + DRAWITEMSTRUCT64_LOCAL.hDC], LISTBOX_TEXT_SELECTED

The difference is that a ListBox contains many entries. itemID identifies which entry is being drawn, and the owner-draw routine asks the ListBox for that row's text.

WM_DRAWITEMitemID → LB_GETTEXT
mov     esi, [rbx + DRAWITEMSTRUCT64_LOCAL.itemID]
cmp     esi, -1
je      .draw_focus

invoke SendMessageW, [rbx + DRAWITEMSTRUCT64_LOCAL.hwndItem],\
       LB_GETTEXT, rsi, DrawItemTextBuffer

The source does not keep a second “this row is selected” flag. The ListBox already owns that state, so painting reads the native ODS_SELECTED bit.

6. Click an item: LBN_SELCHANGE arrives through WM_COMMAND

The demo begins with the instruction “Click one of the items shown in the window.” Clicking an item lets the native ListBox change its own selection first. It then notifies the parent.

WM_COMMANDdecode the ListBox notification
.wmcommand:
        mov     eax, dword [wparam]
        mov     ecx, eax

        and     eax, 0FFFFh
        cmp     eax, IDC_LISTBOX
        jne     .default

        shr     ecx, 16
        cmp     ecx, LISTBOX_LBN_SELCHANGE
        jne     .default

        mov     rax, [lparam]
        cmp     rax, [hListBox]
        jne     .default

This is the same parent message family used by the Button, but the notification is different:

LOWORD(wParam) = IDC_LISTBOX HIWORD(wParam) = LBN_SELCHANGE lParam = ListBox HWND

7. Ask the ListBox what it selected

LBN_SELCHANGE does not require the parent to invent or predict the selected index. The control has already changed its internal state, so the parent simply queries it.

WM_COMMANDLB_GETCURSEL then LB_GETTEXT
invoke SendMessageW, [hListBox], LB_GETCURSEL, 0, 0
cmp     eax, -1
je      .selection_unavailable

mov     esi, eax
mov     [CurrentSelection], eax

invoke SendMessageW, [hListBox], LB_GETTEXT, rsi, SelectedTextBuffer

LB_GETCURSEL returns the current selected index. LB_GETTEXT then retrieves that item's string. This is a clean example of native state ownership: the control is authoritative; the application asks for the result.

8. Mirror only the state the parent needs

The parent wants to paint Selected: TreeView above the child, so the source mirrors the selected index and text into small application-owned values.

.dataapplication mirror + owned handles
CurrentSelection     dd -1
SelectedTextBuffer   rw LISTBOX_TEXT_CAPACITY
DrawItemTextBuffer   rw LISTBOX_TEXT_CAPACITY

MainWindow           dq 0
hListBox             dq 0
hUiFont              dq 0
hListBrushNormal     dq 0
hListBrushSelected   dq 0

This mirror does not replace the ListBox's selection. It exists only because the parent has its own visual output to render. If the parent did not need that status line, there would be no reason to duplicate the selected text at all.

9. Selection changes state; WM_PAINT renders it

The LBN_SELCHANGE handler does not paint the status line directly. It invalidates only the parent region above the ListBox.

WM_COMMANDinvalidate only the status area
invoke GetClientRect, [hwnd], statusInvalidateRect

mov     eax, [ScaledTitleHeight]
mov     [statusInvalidateRect.top], eax

mov     eax, [ListBoxY]
mov     [statusInvalidateRect.bottom], eax

invoke InvalidateRect, [hwnd], statusInvalidateRect, FALSE

Then the normal parent WM_PAINT path renders either the beginner instruction or the mirrored selection.

PaintWindowbefore a selection exists
cmp     dword [CurrentSelection], -1
jne     .paint_selected_status

invoke SetTextColor, [hdc], STATUS_TEXT_DIM
invoke DrawTextW, [hdc], StatusPrompt, -1, statusRect,\
       DT_LEFT + DT_VCENTER + DT_SINGLELINE
PaintWindowafter a selection exists
invoke SetTextColor, [hdc], STATUS_TEXT_DIM
invoke DrawTextW, [hdc], StatusLabel, -1, statusLabelRect,\
       DT_LEFT + DT_VCENTER + DT_SINGLELINE

invoke SetTextColor, [hdc], STATUS_TEXT_SELECTED
invoke DrawTextW, [hdc], SelectedTextBuffer, -1, statusValueRect,\
       DT_LEFT + DT_VCENTER + DT_SINGLELINE + DT_END_ELLIPSIS
click item │ ▼ ListBox changes native selection │ ▼ LBN_SELCHANGE │ ▼ LB_GETCURSEL + LB_GETTEXT │ ▼ application mirror changes │ ▼ InvalidateRect │ ▼ WM_PAINT │ ▼ Selected: TreeView

10. Owner-drawn rows do not cover every ListBox pixel

WM_DRAWITEM paints item rows, but there may be unused client area below the last row. WM_CTLCOLORLISTBOX supplies the dark brush for those remaining pixels.

WM_CTLCOLORLISTBOXkeep the whole control dark
.wmctlcolorlistbox:
        mov     rax, [lparam]
        cmp     rax, [hListBox]
        jne     .default

        invoke SetTextColor, [wparam], LISTBOX_TEXT_NORMAL
        invoke SetBkColor, [wparam], LISTBOX_COLOR_NORMAL
        invoke SetBkMode, [wparam], TRANSPARENT

        mov     rax, [hListBrushNormal]

This is why the control stays visually consistent even though only five items are present.

11. Fixed owner-draw height still has to follow DPI

The row height is initially supplied through WM_MEASUREITEM. After a live per-monitor DPI change, the source recalculates its 96-DPI design values and explicitly updates the ListBox's fixed item height.

WM_DPICHANGEDrefresh the fixed row height
call    UpdateScaledValues
call    UpdateUiFont

cmp     [hListBox], 0
je      .dpi_no_list_height

invoke SendMessageW, [hListBox], LB_SETITEMHEIGHT, 0, [ScaledListItemHeight]

The same application-owned HFONT is recreated for the new DPI and reused by the parent status text and the owner-drawn rows.

12. What we learned

The ListBox adds a new state model without abandoning anything learned from the owner-drawn Button.

  • The control is a real native LISTBOX HWND.
  • LBS_OWNERDRAWFIXED reuses the owner-draw model already learned with Button.
  • LBS_HASSTRINGS makes the owner-drawn ListBox store copied strings.
  • LB_ADDSTRING adds items to the control-owned collection.
  • WM_MEASUREITEM can arrive while the child is being created.
  • itemID identifies which ListBox entry WM_DRAWITEM is asking us to paint.
  • ODS_SELECTED comes from the native ListBox state; we do not maintain a duplicate row-selection flag.
  • LBN_SELCHANGE arrives through WM_COMMAND.
  • LB_GETCURSEL queries the control-owned selected index.
  • LB_GETTEXT retrieves the selected string.
  • The application mirrors selection only because the parent wants to paint its own status line.
  • State changes first; InvalidateRect requests painting afterward.
  • WM_CTLCOLORLISTBOX keeps unused ListBox client pixels dark.
  • LB_SETITEMHEIGHT updates the fixed row height after a DPI change.
